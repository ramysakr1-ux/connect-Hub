# The card as an email (version 64, 2 Oct 2026)

Ramy: "that email itself is just too crowded... I want the email to be the
card. The card explains everything, so they don't have to read any of that."

The console's "Email it" was a `mailto:` link, which can only carry plain
text: eight lines of prose and four bare links. Now the console builds the
FRONT of the offer card as HTML (`hub-card-mail.js`: the mark, the headline,
his note, the three demo courses and the film as doors, the price, his name)
and the store sends it.

## The op
```js
case 'sendCard': {
  requireOwner_(owner);
  // to (one address), subject, html (<= 60 000 chars), text (plain alternative),
  // copy (an optional bcc, kept out when it equals `to`)
  sendAs_({ to, subject, htmlBody, body, name: 'Ramy — Connect Lite', replyTo: FROM_, bcc? });
  return { sent, copy, from };
}
```
Anchor: inserted immediately before `case 'createCourse': {`.

`sendAs_` gained a `bcc` and now passes `msg.body` as the plain-text part:
anchor `GmailApp.sendEmail(msg.to, msg.subject, '', { htmlBody: msg.htmlBody,
name: msg.name, replyTo: msg.replyTo, from: FROM_ });` replaced by an `opt`
object with `bcc` added only when set.

Refusals, all verified live: no owner key → "Not yours to open"; a bad
address → "Type the address the card goes to"; no HTML → "The card is empty".

## What still blocks the send (his click, not code)
The web app has never been authorised to send mail: the first live call
answered *"Specified permissions are not sufficient to call MailApp.sendEmail.
Required: …/auth/script.send_mail"*. The owner authorises once, in the editor:
pick any function that sends (`sendVolunteerReminders`) → Run → review
permissions → Allow. Until then `sendCard` fails with that message, which the
console shows as "Not sent: …", and the console's **Copy the card to paste
into Gmail** (a rich-text clipboard copy) is the way round it.

The envelope is `lite@celtaconnect.com` only when the account running the
script holds it as a verified "Send mail as" address; otherwise `sendAs_`
falls back to the running account's own address and the op says so in
`from`.

## Why nothing had ever sent (found the same hour)
The manifest (`appsscript.json`, hidden until Project Settings → "Show
manifest") pins `oauthScopes` to spreadsheets, external_request and drive —
no mail scope at all. So MailApp was never allowed: the volunteer reminders
(v56) and the feedback mails (v59) could not have gone out either; their
`try/catch` per course swallowed the refusal and the timer reported 0% errors.
Version 65 adds `script.send_mail` (MailApp) and `https://mail.google.com/`
(GmailApp: send-as alias and `getAliases`). New scopes need the owner's
consent once: Run any function in the editor → Review permissions → Allow.

**Resolved 13:20:** Ramy replaced the manifest (five scopes), ran
`sendVolunteerReminders` once and allowed the permissions, and deployed
**version 65**. `sendCard` then sent the card to ramysakr1@gmail.com — the
first mail the store has ever sent. The envelope was his personal address:
`from` answered "lite@ is not yet a send-as there".
