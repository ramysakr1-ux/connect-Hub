# The Course admin PIN (10 Nov 2026, version 210)

**Why.** A second tutor joins C/21 on the one tutor link every tutor shares,
and that link opens Course admin: remove a trainee, rotate the links. Ramy:
"a password to the course admin ... set by the course admin when they're
setting up the course ... four numbers, easy one."

**The change.** A course may keep a four-number PIN beside its other PINs
(`pins.admin`, a salted hash, never the number).

    { op: 'adminPin', key, adminPin? }      -> { set, ok }     a read; Course admin's door asks it
    { op: 'setAdminPin', key, pin, adminPin? }                  choose it, or change it with the current one
    { op: 'clearAdminPin', owner, course }                      a forgotten one; the owner only, from the console

While one is set, these are refused without it ("Admin PIN required",
"Wrong admin PIN"), whatever page asks: `removeTrainee`, `purgeTrainee`,
`reissueTrainee`, `rotateKey`, `rotateAssessorKey`. The owner's key passes.
Five wrong tries close it for ten minutes; the count is a script property
(`admintries:<course>`), not part of the course, so a wrong try moves no
version. A tutor's boot says whether one is set (`adminPin: true|false`).

A course with no PIN behaves exactly as before.

**Not in this step.** Settings, the timetable and the TP points are still
written by any tutor's page; the door keeps a tutor without the PIN out of
Course admin, but the store does not yet refuse those writes. That is the
second step, after C/21 has started.

**The pages.** `hub-store.js` sends this device's PIN (`hub:apin`) with a
tutor's calls and asks through `hub-pin.js` when the store asks.
`6_centre_admin_dashboard.html` has the door and the card (Course links);
`14_owner.html` has "Clear a forgotten Course admin PIN" under a course's ⋯.

**Old store, new pages.** v209 and earlier answer "Unknown op" to the door:
the room opens as it always did, and the card is not shown (the `pins`
answer has no `admin`). So the pages are safe to push first.

**Deploy.** `clasp push` and a new version, as for v209 (the Pool set read),
which is still waiting: one deploy carries both.
