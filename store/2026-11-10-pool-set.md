# A Pool set arrives complete (10 Nov 2026, version 209)

**Why.** Ramy, setting up C/21: "the audio for the TP points and the pages
should just be there. All the time ... If someone is using Connect, then they
get it with the pages and with the audio. They inherit the whole thing. It's a
set." Pointing at a PDF "should only apply if someone wants to use their own
books."

Until now a set taken from the TP Point Pool arrived with its writing and the
NAMES of its pages and tracks, and every course cut the pages out of its own
PDF. The library course has held every page and every recording all along
(14 sets, 1,105 pages, 416 recordings); nothing handed them over.

**The change.** One read:

    { op: 'poolSet', key: <a tutor's key>, set: 's9' }
      -> { set: 's9', found: true, data: <the set, whole> }

A tutor's key (or the owner's) and nobody else: not a trainee's token, not an
assessor's key, not an anonymous caller. It is in `READ_OPS_`, so it moves no
course's version. The library course is found by its name ("TP point library")
the first time and remembered by id in the script property `LIBRARY_COURSE`.

**The pages.** `hub-shared.js` `hubPoolTake` asks for the set when one is taken
(on TP points and on the set page) and `hubPoolFill` lays it over the public
copy: a page gets its file where book and page number agree, a track line its
link where the track's name agrees, a day its one PDF. The public file is
still what is written into the course; only links are added.

**Old store, new pages.** The op is unknown to v208, the call fails, and the
set arrives as before, to be pointed at the centre's own PDF. So the pages can
go live before the store does.

**To deploy.** `clasp push` and a new version of the web app, as usual.
Then take any Pool set on a scratch course: the note should read
"… is on the course, with its 83 pages and 22 recordings".
